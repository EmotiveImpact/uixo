# Shared-shell parity audit — 12 September 2026

The original integration exposed two applications with separate theme state and navigation. Legacy in-page navigation bypassed the visitor redirect. The React detail omitted automatic acquisition, compatibility, evidence references, redistribution, editorial status and saving.

## Consolidated

- Assets, sources, saved assets, connection instructions and guide now use the React sidebar, theme and account controls.
- Legacy registry entry URLs preserve query parameters and redirect into the shared shell. The legacy script no longer boots a second app.
- Desktop asset grid has three columns, with two on tablets and one on narrow phones.
- Search is a prominent content form; pricing stays in the top menu. Source, framework, format and commercial-use filters still compose.
- Detail has a large preview and two-column project/licence layout, automatic acquisition with cancellation on variant change, dependencies, project compatibility, licence text, evidence references, saving and share links.
- Review, scout and jobs have shared-shell operator screens using the existing server authorization. No credentials are stored in browser storage.
- Preview captions distinguish original SVGs from component illustrations.

## Remaining product limitations

- Website lists and saved asset IDs sync through separate typed account snapshots. Guest saves migrate once, account ownership is isolated, and optimistic revisions reconcile cross-device edits.
- Component illustrations are not verified upstream renders. A source-pinned component rendering pipeline remains future work.
- Signed-in curator JWT acceptance and actual remote indexing/publication need separate live acceptance. The operator UI does not grant access.
- Discovery is keyword matching, not semantic search. The catalogue still contains the 67 approved captured records.
